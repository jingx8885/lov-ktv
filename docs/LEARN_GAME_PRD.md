# 游戏板块修复需求文档

## 1. 背景与目标

游戏板块是围绕当前歌曲歌词的学习与互动玩法，包含课程路径、自由练习、歌词测验（Quiz）、点词音游（Tap）、翻唱挑战（Echo）和错题本。

本次目标不是增加新玩法，而是把现有流程修到可稳定上线：

- 每个课程知识点都能被覆盖，长歌曲不会出现“永远无法通关”。
- 课程解锁、成绩和错题数据由服务端校验，不能通过空提交刷进度。
- 进入、退出、切歌、网络慢、音频失败、麦克风拒绝等异常路径都能收敛到可理解的状态。
- 成绩保存失败必须明确告知用户，不能显示“完成”但实际未保存。
- 桌面端长路径可以滚动，移动端保持现有布局。

## 2. 用户流程

### 2.1 正常流程

1. 用户在听歌页点击“游戏”。
2. 若歌曲或歌词仍在加载，显示加载态；加载完成后进入游戏首页。
3. 首页展示歌曲、目标进度、课程路径、错题本和自由练习。
4. 用户只能进入当前 `ready` 或已完成的技能；锁定技能不可通过接口绕过。
5. 课程玩法完成后提交成绩，服务端校验并返回最新 campaign。
6. 成绩保存成功后显示分数；失败时保留结果并提供重试，不伪装成已保存。
7. 用户可以重做、换玩法、进入错题本或返回听歌。

### 2.2 中断流程

- 用户在任意异步加载期间退出：旧请求返回后不得重新打开游戏或暂停播放器。
- 用户切歌：旧歌曲的学习请求、倒计时、录音和混音必须失效。
- 音频无法播放：显示错误提示，并提供退出/重试路径。
- 麦克风拒绝或不可用：恢复倍速、人声开关和播放器状态。

## 3. 功能需求

### FR-1 题目覆盖与通关可达

- 一个 unit 内所有词汇和句子知识点必须最终有机会出题。
- 单次 lesson 可限制题量，但重复进入必须轮换或只抽取未掌握知识点，不能固定截断同一批题。
- `goal.words.done`、`goal.sentences.done` 的目标必须可通过正常操作达到。
- 课程总进度、技能进度、错题本数据保持一致。

### FR-2 服务端进度与提交校验

- GET lesson 校验 unit 是否存在、skill 是否有效，以及该技能是否处于 `ready`/已完成状态。
- POST lesson/review 必须校验提交内容属于服务端生成的 lesson：题目 ID、知识点 key、答案范围和题量均需合法。
- `pct` 必须限制在 0~100；服务端对选择题按答案重新计算分数。
- 同一轮提交具备幂等性，重复请求不会重复增加 attempts、wrong_count 或 mastery streak。
- review 只允许提交当前错题本中的题目。

### FR-3 异步生命周期

- 每次进入、退出、切歌都生成新的学习会话代际；旧请求返回后不得改变当前 UI 或播放器。
- 所有倒计时、音频窗口、录音、混音任务都能被退出操作取消或安全忽略。

### FR-4 加载态与错误态

- 游戏入口在歌曲/歌词/课程加载时显示 loading，避免误报“没有歌曲/没有歌词”。
- 音频播放、歌词加载、课程加载、麦克风初始化、混音和成绩保存失败，都显示可理解的错误提示。
- 错误状态至少提供返回首页或重试路径。

### FR-5 播放器状态恢复

- 游戏退出或初始化失败后恢复进入游戏前的人声开关和 playbackRate。
- 不改变用户原有播放顺序、当前歌曲和队列。

### FR-6 桌面端可用性

- 900px 以上屏幕的课程首页在 unit 较多时可滚动访问全部内容。
- 不影响手机端纵向滚动和安全区适配。

## 4. 非功能要求

- 不引入 Torch、Whisper 或新的运行时依赖。
- 不改变现有 API 路径；允许增加内部字段和幂等校验字段。
- 现有后端测试全部通过；新增测试覆盖上述异常和长歌曲场景。
- 不记录密钥、录音内容或用户隐私。

## 5. 验收标准

1. 12 个以上词汇的 unit，重复完成课程后可以覆盖并掌握全部词汇，campaign 最终可 cleared。
2. 空 answers + `pct=100` 的提交不能把技能标记为 mastered。
3. 直接请求 locked unit 返回 403/409，不返回 lesson 内容。
4. 点击游戏后立即返回，异步请求完成不会重新弹出游戏或暂停播放器。
5. 切歌后旧歌曲的请求、录音和混音不会写入新歌曲状态。
6. 麦克风拒绝、音频播放失败、成绩保存失败均有提示且可退出/重试。
7. 桌面端可以滚动访问所有 unit。
8. 后端全量测试和前端游戏相关 lint/check 通过。

## 6. 本次交付范围

- 后端：题目覆盖、lesson 解锁校验、提交校验、幂等、成绩重算、错误码。
- 前端：生命周期代际、加载态、错误态、播放器恢复、提交失败重试、桌面滚动。
- 测试：后端 API/生成器回归测试，前端静态契约测试和可测试的纯函数测试。
